# Validation

How the evidence for the method is produced. The simulated windows are checked against the official ZARC windows; nothing here proves the recommendations right in a given field, and the reported probability is a historical success frequency, not a calibrated probability.

## What is checked

| Evidence | How to reproduce | What it shows |
| --- | --- | --- |
| ET0 against the FAO-56 worked example (Example 18: Ra 41.09, ET0 3.9 mm/day) | `make test` (`backend/tests/unit/test_et0.py`) | The Penman-Monteith implementation matches the bulletin. |
| Water-balance properties (no stress with plenty of rain, more rain or stored water never lowers ETa/ETc, seasons independent, irrigation removes stress) | `make test` (`backend/tests/unit/test_water_balance.py`) | The balance behaves as FAO-56 describes. |
| Window selection, confidence and Wilson band against the contract examples | `make test` (`backend/tests/unit/test_windows.py`) | The live ranking logic matches the mock that defines the contract. |
| Response shapes against the JSON Schemas | `make test` with the database up (`backend/tests/contract`) | The API honors the contract. |
| Agreement with ZARC per crop (Spearman of the 36 simulated frequencies against the recommended dekads, median over municipality and soil pairs, threshold 0.7) | `python -m data validate gate` | Whether the engine reproduces the official window. Stored on each crop and served by `GET /api/v1/crops`. |
| Pilot reproduction, sensitivity of the ranking, IMERG against POWER rain, PAM check | `python -m data validate report` (writes [report.md](report.md)) | How close the engine is to the proposal's prototype, how stable the ranking is to the soil and rain assumptions, and how much the rain sources disagree. |
| Agreement with ZARC at one place | applied on every `POST /api/v1/recommendations` | The per-location gate that decides whether a crop is ranked or excluded as `gate_failed`. |

The commands for the gate and the precomputation are in [../../data/README.md](../../data/README.md); the gate implementation and its caveats are in [../../data/validate/README.md](../../data/validate/README.md).

## Current gate result

Statewide medians from the last run (also in [report.md](report.md) and `data/demo/crops.csv.gz`): peanut 0.85, sorghum 0.81, sunflower 0.75 and cotton 0.74 pass; cowpea 0.53, maize 0.64 and castor -0.09 fail. Common bean, pearl millet, cassava and sweet potato have no ZARC rows and stay `not_run`. Per location the verdict can differ from the statewide one (cowpea passes at the pilot municipality). Re-run the gate to refresh these numbers; they change with the engine, the soil assumptions and the data.

## Limits

- ZARC is derived from a water balance, so agreement is not independent validation. A crop that agrees is reproducing the official method; a crop that disagrees (castor) shows where a simple water balance misses what ZARC encodes.
- The meaning of ZARC's 0, 20, 30 and 40 as risk percent and the Jan 1-10 start of dekad 1 are unconfirmed.
- PAM yields are municipal, pool rainfed and irrigated areas and are shown as context, not used to validate.
- The soil available-water values for classes 1 and 3 are project assumptions; their sensitivity has not been quantified here.

## Report

[report.md](report.md) is generated by `python -m data validate report` from the database (run after `etl precompute-windows` and `validate gate`) and the committed IMERG sample; edit the generator in `data/validate/report.py`, not the file. It covers the pilot reproduction against the proposal's prototype, the quality gate table, the sensitivity of the ranking, the IMERG against POWER rain comparison for 2024 and a weak check against PAM yields. Regenerating it rewrites the tables unformatted, so run `npm run format` from `web/` afterwards if the format check fails.
